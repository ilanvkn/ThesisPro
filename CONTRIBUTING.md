# Contributing to ThesisPro

Start a branch for one concrete change. Explain the user problem, the resulting behaviour and the checks you actually ran. Preserve compatibility with existing local libraries.

Use only invented test fixtures or material you have permission to redistribute. Do not commit private papers, student IDs, participant records, credentials, proprietary evidence or downloaded publications. Showcase cards are topic examples, not an invitation to copy an author's findings.

For evidence features, test changed revisions, missing sources, contradictory findings, rejected operations and preserved history. Do not treat filled fields, word targets or role counts as academic completion. Include failures and scope limitations in your contribution.

Run the plugin unit tests and appropriate native checks described in README.md. A passing build is not evidence that a research claim is true. Report security issues according to SECURITY.md.
